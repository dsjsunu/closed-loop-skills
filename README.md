# closed-loop-skills

个人 AI 工作流技能：定位根因 → 方案确认 → 修复 → 验证与返工 → 候选交付 → 人工验收。

源于文档发布维护中的闭环经验，通用层不包含客户数据、业务源码或内部地址。适合代码、数据转换、文档渲染等缺陷修复；不是任何任务都必须运行的重型流程。

## 当前包含

- `skills/closed-loop-repair/`：可独立安装的 skill。
- 项目接入、任务记录和证据检查用法。
- 无第三方依赖的证据检查器；绑定源码、输入、候选、报告和已确认方案。
- `examples/`：全部为自造示例，不可当作已执行的验证结果。
- `tests/`：用临时项目验证数据分流、版本漂移、输入保护、方案与报告绑定等行为。

## 安装

在 Codex 中使用 skill-installer，从此仓库安装 `skills/closed-loop-repair`；也可以把该文件夹复制到当前环境支持的个人 skills 目录或项目的 `.agents/skills/`。不要用新 skill 覆盖项目已有的规则。

调用示例：

```text
使用 $closed-loop-repair 检查这个表格为什么缺线。
先区分数据还是渲染问题，给出具体根因、修复方案和预期效果。
我确认后再修改，自己对比截图并通过项目门禁，再交给我验收。
```

## 使用边界

Skill 提供决策与操作指导，不是后台调度器。模型需要实际可用的文件、渲染、测试等工具；无人值守持续执行还需另外配置运行环境和触发方式。

自动门禁通过只代表 `ready_for_human`，不代表用户验收、合入或部署。检查器不判断截图语义、不执行项目测试、不认证确认者身份，也不能阻止恶意修改快照。执行日志、图片审阅与人工确认必须真实发生。

项目适配只需明确源数据、实现层、产物、复现命令和完成标准。航空 PDF、Web 和数据工具可共用流程，但各自使用适合的验证方法，不强求都截图。

## 开发验证

```text
python -m unittest discover -s tests -v
```

`examples/github-actions-test.yml` 是 Windows/Linux 自动测试配置示例，尚未启用。需要时将其放入 `.github/workflows/`，并使用具备相应权限的凭据推送。

第一版聚焦一个完整 skill；后续只根据真实跨项目使用中重复出现的需求拆分技能，不预先堆叠流程。
