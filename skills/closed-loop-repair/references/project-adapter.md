# 项目接入

## 必须明确

1. 项目根目录、现有规则、当前任务与期望行为；当前代理能读取、执行和查看哪些内容。
2. 原始输入、实际生效源码/配置、生成产物各在哪。数据错误由谁处理。
3. 复现/构建命令及运行环境。命令来自项目，不猜测、不自动安装或发布。
4. 本任务的验证方法、正常反例、必须通过的门禁。
5. 哪些动作已获授权，哪些需要方案确认或人工验收。

轻量任务可直接记录这些信息。需要机器检查时使用仓库 examples/project.json；路径均相对项目根，不含用户名、私有远端或业务数据。

## 领域映射

| 项目 | 输入问题 | 实现问题 | 验证 |
| --- | --- | --- | --- |
| Web | API 返回字段或内容错误 | 组件、样式或状态处理错误 | 数据响应、页面截图、交互与相关测试 |
| 后端 API | 请求字段不符合契约 | 合法请求计算错误，或非法请求未按契约返回错误 | 请求/响应、状态码、接口与边界测试 |
| 数据处理 | 原始记录缺失、单位错误 | 清洗、计算或字段映射错误 | 样本追溯、输出断言、边界与回归 |
| 命令行工具 | 参数/配置不满足契约 | 解析或执行逻辑错误 | 最小复现、返回码、输出和正常输入测试 |
| 自动化任务 | 上游文件缺失或服务返回错误数据 | 调度参数、路径、重试或处理逻辑错误 | 受控执行、任务日志、幂等与失败恢复检查 |
| 文档生成 | 结构化输入属性错误 | 转换规则未使用正确属性 | 结构证据、前后图像、内容完整性与回归 |

上述只是映射，不等于自动授权修数据。特定航空项目的门禁、数据保护与验收规则仍属于项目，不进入通用层。

## 配置字段

- `source_roots`：需要追踪的实现源码目录/文件。
- `protected_roots`：本任务不得修改的数据目录/文件，同时绑定输入版本。
- `required_checks`：项目真实检查的名称，至少包含目标效果与回归检查；视觉任务还需视觉检查。
- `visual`：是否必须提供 before/after 截图和视觉检查。
- `visual_check`：视觉任务对应的检查名称，必须出现在 `required_checks` 中。

源码根与保护根不得重叠。证据、任务记录、缓存和生成文件放在这些根之外，否则记录本身会使快照失效。清单捕获会遍历配置根的全部文件，避免把巨大仓库根目录直接填进去。
