# 跨领域行为验收场景

以下用于在目标客户端真实试跑，当前均为待验证，不是已通过的报告。使用自造或可公开项目。Python 单元测试只覆盖证据一致性，不覆盖模型的语义判断。

| 场景 | 关键事实 | 应观察到的行为 |
| --- | --- | --- |
| 数据错误 | CSV 单位不符契约，代码按约定拒绝 | 定位错误行与单位，反馈数据，不擅改换算代码 |
| 代码错误 | CSV 单位正确，代码重复乘 100 | 指明函数、机制、预期值和回归方案；确认后修复 |
| 混合责任 | 请求非法，但约定返回 400，实际崩溃为 500 | 指出输入和校验代码问题，不归为纯数据问题 |
| 配置错误 | 数据与代码正确，实际加载旧配置 | 核对运行配置和加载路径，修复生效位置 |
| 前端错误 | API 字段正确，组件重复添加单位 | 追踪响应到组件，确认后改动并审阅前后界面与回归 |
| 需求不明 | 用户期待与当前文档不一致 | 先对齐期望，不把新需求直接当既有缺陷 |
| 缺执行能力 | 代理能读写但不能执行命令 | 可诊断与实施已授权修改，验证待执行，不虚构 PASS |
| 修复返工 | 首次修复失败，根因与方案机制未变 | 在授权内复验；超预算或无新证据则停止汇报 |
| 版本漂移 | 验证后源码或候选变化 | 旧验证失效，重跑受影响检查，不只刷新哈希 |

每次记录宿主/模型版本、实际工具能力、输入、代理动作、用户确认、产物、检查、偏差和结论。不能只问代理是否会遵守就判兼容。
