## 角色和授权

主执行者维护任务状态、归因、方案、实现、验证和最终交付。独立审查者使用独立代理上下文，只读核查实际文件、调用链与结果，不修改源码、输入、候选或验收记录。主执行者保存其原始返回内容，不替审查者撰写 PASS。

项目要求每次修复独立审查时必须执行，风险等级只改变深度。没有此要求时按风险和宿主能力选择；普通自查须如实注明。工具不可用、任务未送达或材料无法读取均不算审查通过。继承对话的子代理仍须自行核验文件，不能把主执行者结论当作证据。

只有用户或项目明确授权时才分派并行实现。开始前固定每位实现者的文件所有权、基线、输入、交付格式和禁止触碰区域；共享文件由主执行者串行集成。审查授权不等于并行写入、创建其他聊天、外发消息或推送授权。

## 一次可复核的审查

1. 主执行者准备原始需求、规则入口、明确的基线/候选路径、逐文件差异及 SHA256、目标范围、验证命令和证据。敏感材料留在项目，不复制到公共技能仓库。
2. 启动真实审查代理，确认其收到任务并能访问材料。审查者独立检查需求是否满足、根因与机制是否成立、内容是否遗漏/重复、正常反例和相关历史修复是否回退，以及授权/冻结/部署边界。
3. 保存真实代理标识、时间、实际检查范围、文件/候选哈希、发现、未验证项和 PASS/FAIL/MANUAL_REVIEW/BLOCKED。空返回、构建成功、语法预检都不等于独立审查。
4. 主执行者处理每项发现，保留修复或误报证据。阻断项必须关闭；延期项记录影响和理由。修复后请独立审查者复核新差异及关联回归，不能自行宣布其发现已关闭。
5. 结果仅绑定已核验的哈希。源码、配置、输入或候选改变后补审受影响差异，并重跑对应验证。默认最多两轮全范围审查，之后集中检查新差异；轮次用尽不放行阻断项。

需要记录时复制 [变更审查模板](change-review-template.md) 到项目证据目录，不把空模板当作真实报告。

## 与项目闭环的衔接

项目接入 → 归因与结构证据 → 已确认方案 → 冻结当前在用基线 → 隔离修改 → 重建候选 → 验证/有界返工 → 独立审查及处置 → 冻结候选 → 人工验收 → 获授权后集成/部署 → 部署后核验。

- 基线包括当前在用的未提交文件和覆盖层，不能仅用旧 HEAD。冻结记录不可覆盖，历史工作树缺创建基线时重新集成，不补写当前哈希伪装创建记录。
- 规则修复先归纳稳定结构、同级关系与属性，列出全部命中和正常反例；跨版本/语言/目标比较已有正确实现，核对数据差异后复用。禁止靠固定业务 ID、标题或文案掩盖问题。
- 选择性转换必须列出每类源节点的输出去向，核对对应结果的文字、顺序、次数及链接。零报警、生成成功、全局搜到一句文字均不能证明内容完整。
- 集成时三方核对创建基线、当前正式源码和候选，逐文件声明修改，保留并发成果。正式基线变化使旧部署候选失效；重新集成、验证并按项目要求重新验收，不能只刷新哈希保留旧 PASS。
- 验收绑定具体候选及源码；部署走项目既有门禁、锁、版本规则和回滚入口。部署后核对实际版本及相关历史回归。候选就绪、已验收和已部署分别记录，禁止整目录覆盖绕过门禁。

这些是代理执行要求。当前 `evidence_gate.py` 仅核对既有证据一致性，**不校验独立审查报告、代理身份、部署基线、内容完整性或部署权限**，也未启用 CI/分支保护。需要机器强制时由项目另行实现并测试，不宣称已有拦截能力。
